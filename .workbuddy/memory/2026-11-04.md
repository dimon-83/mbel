# 2026-11-04

- 评估 wasm 给第三方语言调用的现状，实测确认结构性阻塞：0.4.1 产物是 js-string ABI（wasm-gc + `use-js-builtin-string`），Node 24 + `builtins:['js-string']` + `importedStringConstants:'_'` 才能实例化；Node 22（同参数）与 Node 24（裸编译）都报 `Import #1 "_" is not an object or function`，Node 20 无 GC 提案。wasmtime/wazero 无 JS String Builtins，Rust/Python/Go 宿主无法接入。
- **关键发现：可移植路径不用改引擎。** `moon build --target wasm` 编译当前源码 0 错误；声明 `"wasm"` link profile 后 release 产物 740,102 B（js-string 版 605,590 B，+22%），导出仍是那 8 个 + `_start`，导入只有 `wasi_snapshot_preview1.fd_write` 与 `__moonbit_time_unstable.now`。纯宿主（DataView，无 V8/js-string）实测：`eval_expr("a * 2 + 1", {"a":20}, "vm")` → 41；`eval_checked('1 + "a"')` → 检查器信封；`dump_ast("1 + 2")` → `bin(+,int:1,int:2)`。
- **字符串布局（逆向得到，必须锁）**：MVP target 的 `String` = 指针指向 UTF-16LE 数据，`ptr-4` 是 u32 字符数，尾部 `0x0000`。双向验证通过（宿主按此写 buffer 传参被正确解析）。这是运行时内部布局，因此提案要求写进文档 + 在 `check_abi.mjs` 加 `--cabi` 断言 + 导出 `abi_layout()`，让工具链漂移变成 CI 红灯而不是客户现场故障。
- **DCE 陷阱**：不声明 `"wasm"` link profile 时构建成功，但产物只有 259 B（仅 `memory`+`_start`），导出全被死代码消除——容易误判成"后端不支持"。
- 性能实测（0.4.1 js-string 产物）：`eval_expr` 0.004 ms/次；`eval_with_functions` 带 200 个函数 **0.475 ms/次（106×）**，全是每次重解析 + 重 checked 注册的重复工作 → session handle 是最高 ROI 项（吸收 0001 P1）。
- 契约缺口：manifest 声明了 `$code` 但代码从不发出（只有 `$error`）；`limits` 只读、`Engine::set_limits` 未导出；错误位置埋在消息文本里；manifest 在 `web.mbt:22` 手写，与 abi.json 双源（bump 要改三处）。
- 对抗输入实测不 trap：50k 嵌套括号/数组、50k 项加法链都返回 `$error`，2 MB env 正常求值。

- **C-ABI 字符串约定（实测锁定）**：String 参数=单 i32 指针；`ptr-4` u32 字符数 + UTF-16LE 数据 + 双 NUL；返回值同读法。`_start` 在 start section 实例化时自动执行。导入：`wasi_snapshot_preview1.fd_write`（桩可）+ `__moonbit_time_unstable.now`（**i64** 返回，Unix ms）。
